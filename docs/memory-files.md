# 记忆文件与 I/O 边界

MEMORY、SOUL、USER 与 HEARTBEAT 仍是工作区中的 UTF-8 文本文件。本批统一这些文件的受限读写路径，修复链接越界、固定临时文件、无限读入和并发追加丢失更新的边界；没有实现 embeddings、向量索引或语义检索。真实二进制 fixture 与跨平台 CI 的本批验收状态见[验证记录](validation.md)。

## 配置与授权

```toml
[memory]
path = "notes/MEMORY.md"

[identity]
soul_path = "notes/SOUL.md"
user_path = "notes/USER.md"

[tools.memory_write]
enabled = false
```

路径相对于 `agent.workspace_path`，不会展开 `~` 或环境变量。禁止绝对路径、`..`、空路径，单路径最多 1024 UTF-8 字节和 64 个组件。工作区根目录及其上级目录必须由管理员控制；工作区内部逐级打开父目录，再使用目录句柄访问文件，拒绝符号链接父目录，以及符号链接、硬链接、目录、FIFO、socket 等非常规目标。不存在的父目录可在写入时安全创建。

`memory_read` 的 `file` 参数保持 `MEMORY.md`、`SOUL.md`、`USER.md`、`AGENTS.md` 四个逻辑名字：前三个分别读取配置路径，`AGENTS.md` 保持工作区根路径。配置路径缺失时不回退读取默认同名文件。CLI `memory show`、`soul show`、`user show` 使用相同的受限读路径。

`tools.memory_write.enabled` 同时控制 `memory_write` 和兼容名字 `memory_append`；关闭后两者都不注册、不进入模型工具目录，也不能通过原生工具调用绕过。`memory_write` 的 `mode=append/overwrite` 对应追加/覆盖；`memory_append` 的 `replace=false/true` 对应相同操作，只能写配置的 MEMORY 路径。

这是记忆工具的授权开关。通用文件写工具、可写 exec 沙箱和外部 MCP 工具需另行审查与授权；允许它们编辑工作区仍可能改变记忆。要求整个工作区只读时，必须一并限制这些入口和文件系统权限。独立用户继续使用各自工作区和运行实例，见[网关部署](gateway.md)。

## 字节与资源上限

所有大小均按 UTF-8 字节计算，KiB 为 1024 字节。原生工具调用的参数 JSON 另有 16 KiB 预检上限，因此不能通过单次原生工具调用提交 32 KiB 正文；文件总量边界通过有界追加生效。

| 操作 | 上限与超限行为 |
|---|---|
| `memory_write`、`memory_append`、`soul_write`、`user_write` | 最终文件最多 32 KiB；追加包含已有内容和新增分隔换行，超限拒绝且保留原文件；覆盖可将大文件替换为合法的小文件 |
| MEMORY / SOUL / USER 提示注入、`memory_read`、CLI 展示与工作区默认文件加载 | 最多读取 32 KiB 正文；在完整 UTF-8 边界截断；工具/CLI 展示说明截断，提示注入记录警告 |
| HEARTBEAT | 最多 32 KiB；超限拒绝整个轮次且不调用模型，避免执行残缺指令；缺失或空白文件跳过 |
| `memory_search` | 大小写不敏感的关键词子串检索；每文件最多读取前 512 KiB，超限附截断提示；无效 UTF-8 拒绝 |
| 检索请求与结果 | 最多 16 个输入路径、查询最多 1024 字节、每条摘录最多 1024 字节；默认 5 条、最多 20 条结果；读取前校验全部路径 |
| 检索输出 JSON | 序列化后最多 64 KiB，包含路径、提示和特殊字符转义；超限报错，调用者需减少 `max_results` / `paths` |

读取使用有界句柄读取，不先将超大文件全部装入内存。截断点以外内容不参与提示或检索。文件大小是打开句柄取得的元数据快照；不承诺与同时进行的外部编辑线性一致。异步记忆工具使用独立阻塞任务和全进程 8 个 I/O 许可；容量忙会返回错误，取消等待不会提早释放仍在执行的 I/O 许可。

## 提交、并发与故障处理

Linux/macOS 上，协作写入者先对工作区目录 inode 取得非阻塞独占 `flock`，持有到整个读取、修改和发布结束。锁忙立即返回错误，不自动重试；没有成功回执的追加不能当成已提交。该锁串行化 JiaClaw 记忆写入，不串行化不遵守锁的编辑器或其他文件工具，也不提供分布式文件系统或跨实例事务保证。

写入先在目标目录创建随机、排他创建的临时文件（Unix 权限 0600），写完同步文件，再原子替换目标并同步父目录。旧固定 `<name>.tmp` 文件不会被复用。初始化的“不覆盖”发布使用原子 create-if-absent；正常结束清理本次临时文件。意外退出可能留下 `.jiaclaw-memory-*` 暂存文件，停机核对后才清理，不把暂存文件自动当作已提交记忆。

文件已重命名但父目录同步失败时，错误会要求核对文件；内容可能已经可见，不得盲目重复追加。工具超时、调用方取消或进程中断同样不能提供跨模型轮次的 exactly-once；阻塞写任务可能在等待方取消后完成，恢复前应检查实际文件。磁盘和文件系统需支持本部署的锁、原子发布与同步操作，错误不能被忽略。工作区备份要在停止写入后取得一致快照。

`jiaclaw init` 不带 `--force` 时保留已有工作区；库级初始化只补缺失的默认文件与示例技能。显式 `jiaclaw init --force` 仍会覆盖已有常规默认文件及示例技能，链接或特殊文件会报错。初始化按单文件提交，不是整个工作区事务；中途失败时前面的文件可能已提交。生产工作区先备份，不用 `--force` 代替恢复流程。

## 本批验收

`python3 tests/memory_io.py target/debug/jiaclaw` 通过真实 CLI、HTTP 服务与本机模型协议 fixture，覆盖初始化、原生工具授权、配置路径、UTF-8 与大小限制、恶意链接/特殊文件、旧临时文件守护、目录锁竞争和 HEARTBEAT 拒绝/恢复。所有凭证与文件均为一次性测试数据，不调用真实供应商。

新增 fixture 已在本批 macOS arm64 二进制上完成四组进程验收，全量 Rust 747 项通过，并接入 Linux/macOS CI；跨平台/真实容器以本批 draft PR 最终 head CI 为准。Rust 层的目录句柄、并发追加、失败清理及取消资源测试与整机 fixture 共同提供证据；不以普通协议测试代替断电后的硬件持久性认证或语义检索质量验收。
