# 工作区技能读取与重载合同

技能从管理员配置的 `workspace/skills/<目录>/SKILL.md` 读取。现有 YAML frontmatter、关键词激活、显式 `enabled_skills` 和提示注入继续使用；未提供 frontmatter 名称时采用目录名，未提供描述时采用 Markdown 描述。技能是管理员审核的指令，加载不授予工具权限。

## 文件与容量边界

- workspace 是管理员选择的可信根；根以下通过已有文件工具的目录能力访问。`skills/`、技能子目录、叶文件都拒绝符号链接，包括内部链接和悬空链接。叶文件只允许单链接普通文件，拒绝硬链接、目录、FIFO、设备及无效 UTF-8；Unix 读取使用 NOFOLLOW/NONBLOCK。不会先检查路径再通过环境路径重新打开叶文件。
- 每个原始 SKILL.md 最多 128 KiB，检查文件大小并限制实际读取，增长到上限之外也拒绝，不截断后解析。完整目录最多 64 个有效技能、2 MiB 原始技能文本；顶层所有条目（含无关文件和空目录）最多 256 项。目录扫描同时复用已有 2 秒合作期限和路径/序列化预算，任何不完整扫描失败，不发布任意截取的目录。
- 目录名、声明的 name 和每个 trigger 均为非空的 1..=128 UTF-8 字节，无首尾空白或控制字符；description 最多 2048 UTF-8 字节，triggers 最多 32 项。重复声明名称是完整目录错误。技能按目录名排序；按目录名查找禁止绝对路径、路径穿越和多个组件。
- 单文件 API `Skill::from_file` 的父目录由调用方授权，拒绝该父目录以下的技能目录/叶链接；工作区发现和 find 始终锚定配置的 workspace，不使用已扫描的技能目录作为新的环境权限根。

启动/普通 `skills --verbose` 对单个坏技能告警并跳过；根目录错误、扫描超限、累计容量超限和名称重复使整个扫描失败。Agent 启动的现有容错策略会报告扫描错误并使用空技能表；CLI 对扫描错误非零退出。真实缺少 `skills/` 或缺少 SKILL.md 的普通子目录视为空/非技能；悬空链接不等同于缺少文件。

## 重载、授权与取消

`skills reload --config ...` 严格扫描并非零报告错误，不通知运行中的服务。认证的 `POST /api/skills/reload` 和 Unix SIGHUP 使用同一严格扫描：先完整构建新表，再一次替换进程快照；任一无效文件或目录错误保留旧表。真实删除 skills 根目录后重载可清空表。`GET /api/skills` 返回当前进程的已加载表，不能用磁盘扫描代替该结果。

每个 Agent 的 SkillRegistry 由 HTTP/SIGHUP 和同步 Rust 重载共用一个非排队许可，异步入口在 Tokio 执行线程之外扫描；忙时拒绝新的重载，许可由实际工作持有。独立注册表各自拥有容量，互不占用。HTTP 断开或取消等待不会终止已进入的文件系统调用，该工作仍可能完成并发布新表，须通过原进程 GET 核对。同步 Rust 调用方仍应自行安排阻塞执行资源。

快照替换原子不等于文件系统事务：未协作的编辑器在扫描期间修改多个文件时，可能构成不同编辑时刻的有效组合。目录能力避免通过链接替换逃逸，但本地普通文件系统调用没有强制 wall-clock 截止；合作扫描期限也不是 OS 沙箱。部署时应使用管理员控制的本地工作区，不把不受信网络文件系统的可用性视为已认证。

## 验收与剩余范围

`python3 tests/skills.py <binary>` 驱动真实 CLI 和认证 HTTP：正常加载、超大/无效文本和元数据、符号链接/悬空链接/硬链接/FIFO、根链接、重复名称、失败保留旧表、合法更新及删除根后清空。Rust 回归覆盖文件/目录精确容量边界、确定排序、元数据上限和 find 权限；官方 CI 与四个优化候选均执行本批技能进程回归，各自固定 head 资格另计。

本批只完成现有技能发现的读取和资源边界。后续显式启用的[按需正文工具](skill-read.md)消费这一已加载表并绑定正文 hash；它的固定提交和资格独立验收。来源/版本/校验治理、参考资源按需读取、安装更新撤销、经验自动提炼、跨租户技能授权仍是后续独立能力，不将 Markdown 发现或只读正文工具视为完整技能生态。
