# 管理员技能来源锁

`[agent] skill_lock_required = true` 开启严格锁定，默认关闭以兼容现有目录。锁文件固定为工作区根目录的 `skills.lock.json`，普通 UTF-8 文件，最多 128 KiB、64 条记录；链接、硬链接、FIFO 和未知字段均拒绝。即使 `skills/` 不存在，也必须提供显式空锁。

```json
{
  "version": 1,
  "skills": [{
    "directory": "my-skill",
    "source": {
      "repository": "https://github.com/example/skills",
      "revision": "0123456789abcdef0123456789abcdef01234567",
      "skill_sha256": "替换为完整SKILL.md原始字节的小写SHA256"
    }
  }]
}
```

目录是一级目录名，1..128 UTF-8 字节，无空白、控制字符、斜杠、反斜杠、冒号或 `.`/`..`。地址只接受无凭据、查询串、片段的 HTTPS URL（最多 1024 字节）；修订号是 40 或 64 位小写十六进制 Git object ID。本页版本1的目录声明唯一，已加载名称唯一，锁中的技能与磁盘中实际可加载的技能一一对应。没有 SKILL.md 的未登记普通目录可以存在，登记但文件缺失的目录不能通过。

管理员先独立审查来源修订号及全部 SKILL.md（包括 frontmatter），再用 `shasum -a 256 /实际路径/SKILL.md` 计算精确字节的 SHA-256 并写入锁。JiaClaw 不下载代码或自动生成“可信”锁；地址、修订号只是来源声明，hash 只证明加载字节和管理员锁一致，不能证明发布者身份、签名或安全性。完整原文件 hash 与模型目录的正文 hash 用途不同。声明的参考资源仍在按需读取时核对原始文件 hash，不在发现时打开。

启动、CLI 列表/扫描、doctor 和 HTTP/SIGHUP 热加载使用相同锁策略。必需锁缺失、损坏、未登记技能、登记文件缺失或原始字节漂移均报错；开启锁的启动不能退回空表或宽松发现。doctor 默认只读检查，锁失败返回非零。热加载完整扫描成功后才发布新表；失败保留旧表、来源记录和已有正文。改写磁盘锁不会立即撤销已加载的技能，需要审核后成功热加载。并发与取消沿用每注册表一个实际 reload worker 的容量边界。

认证的 `/api/skills` 在已锁技能上提供 `source` 字段；`skills --verbose` 显示来源声明、修订号和原文件 hash。未开启锁时不读取锁文件、不提供 source 字段。来源记录不进入模型指令，不增加原请求工具白名单或租户权限。库调用者使用 `Skill::from_file` 是低层解析；需要目录锁策略时使用 `SkillDiscovery::with_lock_required(true)` 并同样配置注册表。

锁文件的写入权限属于工作区现有写入权限：已获授权的通用文件工具或本机进程可以改写锁。此功能没有独立路径 ACL 或审批门；需要不可改写的部署应给锁文件与技能目录设置独立只读挂载。地址/修订号/hash 一起变更后，仍须成功热加载才会进入新表。不能把此锁当成对已获工作区写权限的执行者的隔离边界。

此交付只提供管理员声明和内容锁定。签名认证、下载/安装、自动更新、撤销事务、经验记忆和完整技能生态仍待独立实现与验收。

版本2在同一必需锁开关下提供显式布尔加载策略，停用条目保留来源且不读取其叶文件；版本1拒绝 `enabled` 并保持全部启用。只读策略目录与成功重载、已选择工作边界见[持久启停合同](skill-activation.md)。此扩展仍不提供安装或签名认证。
