# Web 发件箱审计与人工核对

内置工作台的“发件箱”供单实例管理员查看渠道投递、核对未知结果和取消同一来源的剩余投递。它复用持久 outbox，不新增发送通道。入站回复和定时通知都能查看；会话聊天与独立用户网关的任务管理继续使用各自的权限入口。

## 进入条件

在 `jiaclaw serve` 的同源工作台输入该实例的 API Token。服务必须配置非空 `http.api_token`（或 `JIACLAW_API_TOKEN`）及 `http.persist = true`。管理入口应只对可信网络开放，远程使用时由受信反向代理提供 HTTPS，部署要求见[渠道指南](channels.md)。

页面使用已有 `GET /api/channels/status` 探测权限与持久化能力，只有成功返回 `running`、`failed`、`stopping` 或 `disabled` 才显示“发件箱”。未配置当前渠道 worker 时，`disabled` 仍允许管理员查看和核对同一数据库内的历史记录。API Token 缺失或无效返回 401；未启用持久化返回 404。页面把探测的 403/404 视为能力不可用，401 则清空当前身份并要求重新连接。

独立用户网关拒绝 `/api/channels/*` 管理路由，普通用户 Key 不能通过此页面取得整个后端的 outbox 权限。发件箱是实例级管理员视图，不按渠道发送者划分权限，也不提供多用户渠道身份绑定。不要把后端管理员 Token 分发给网关普通用户。

## 查看记录

进入“发件箱”后，每页读取 5 条投递，按入库顺序显示渠道、目的地、来源、片段序号与状态。API 的 offset 范围为 0–10000，工作台只在该范围内翻页。翻页请求失败时保留当前页，成功读取并校验目标页后才推进 offset。新增或清理记录可能改变分页位置；分页不是数据库快照，也没有总数或稳定游标承诺。

可点击列表记录，也可在“按投递 ID 查找”输入投递 UUID 直接读取详情，无须逐页扫描。页面独立获取该记录最新状态，而不是把列表中的旧状态直接作为操作依据。详情包含安装与目的地、入站事件 ID 或任务/运行 ID、片段正文、尝试次数、时间、回执及错误。长字段以纯文本显示并明确标注截断；平台或模型返回的 HTML 不会执行。Discord 的持久交互凭据不进入该接口。

| 请求 | 用途 |
|---|---|
| `GET /api/channels/status` | 探测管理员能力并查看渠道 worker 状态 |
| `GET /api/channels/deliveries?limit=5&offset=0` | 返回数组，可同时包含入站回复和定时通知；没有 `next_offset` 字段 |
| `GET /api/channels/deliveries/{id}` | 读取单条最新记录；ID 须是非零、规范小写 UUID，无效 ID 返回 400，不存在返回 404 |
| `POST /api/channels/deliveries/{id}/resolve` | 人工确认送达或取消所属来源的剩余投递；成功返回 204 |

API 列表本身仍支持 `limit=1..100`（默认 50）、`offset=0..10000` 和可选 `event_id`；工作台固定每页 5 条。更多记录状态、容量、去重和清理合同见[管理与恢复 API](channels.md#管理和恢复-api)。页面不执行审计清理，也不提供未知消息的“重试发送”操作。

## 确认未知投递已送达

先在对应平台核对安装、目的地、消息内容和片段，并保存可追踪的消息 ID 或其他实际核查依据。只有 `unknown` 记录可选择“确认已送达”。证据必须非空且不全为空白，长度为 1–4096 **UTF-8 字节**，禁止换行及其他 Unicode 控制字符；中文与 emoji 不能按字符数估算该上限。浏览器和服务端都会检查。

```json
{"action":"delivered","receipt":"平台消息 ID 123；已核对目的地与片段内容"}
```

确认只将这一条未知投递记为 `delivered` 并保存证据，本次管理请求不会重新向平台发送该消息。解除未知阻挡后，后台可能继续发送已经存在的后续片段或其他被该记录阻挡的投递；冷却、权限和安装级限制仍然有效。该操作不恢复已暂停的定时任务，不重跑原 Agent 或工具。

平台回执的 `delivered` 表示平台已接受，不能解释为终端已读。人工标记则依赖管理员提供的核查证据；不要仅凭本地超时、错误提示或没有看到消息就推定投递结果。

## 取消此来源的剩余投递

“取消此来源的剩余投递”作用于**整条入站事件或整次定时运行**，不是只取消当前片段。确认框显示来源 ID、目的地和当前投递 ID；提交前应核对范围。

```json
{"action":"cancel"}
```

页面允许从 `pending`、`retry_wait`、`unknown`、`permanent_failed` 或 `expired` 记录发起取消。服务端在事务中检查实际状态；同一来源仍在 Agent 执行或平台提交时会拒绝，不能以旧详情越过在途保护。取消会保留审计，不撤回平台已经收到的消息，也不会解除已有的平台冷却、恢复暂停的任务或自动运行一个替代任务。

## 超时、冲突和身份切换

发件箱的每个 HTTP 请求最多在浏览器等待 30 秒。这是本地等待期限，关闭页面、取消等待或断网都不能证明服务端操作停止或回滚。

收到 409、网络错误、非预期响应或超时后，页面保留证据草稿，尝试以 GET 重新读取同一投递及列表，不自动重发 POST。若刷新成功，先核对当前状态与回执，再决定是否仍需操作；刷新失败时禁用变更按钮，使用“刷新此记录”取得新状态。即使收到成功的 204，仍须读取最新详情后才显示操作完成；后续读取失败时保留草稿并提示核对。

草稿只在当前身份的页面内存中保留。切换记录有未保存证据时需要确认；切换 Token、重新连接或收到 401 会清空旧身份的列表、详情、证据、聊天和任务草稿，并忽略旧请求的迟到结果。Token 不写入 localStorage、sessionStorage 或 Cookie。刷新或关闭页面会丢失未提交草稿，先保存必要的外部核查依据。

```sh
cargo build --locked -p jiaclaw-host
# 需在 NODE_PATH 中提供 Playwright，并已安装对应 Chromium；CI 固定版本执行。
node tests/outbox_browser.cjs target/debug/jiaclaw
```

本批不需要真实平台或付费模型凭据。浏览器验收不替代目标平台的安装、权限、真实回执及限流认证，也不扩展原 outbox 的恢复保证。
