# 管理员受控修改技能加载策略

`jiaclaw skills set-enabled <一级目录> --enabled true|false --if-manifest-sha256 <64位小写SHA256> --config ...` 只修改已有必需锁中的一条加载策略。必需锁关闭、目录未登记、参数无效、原始manifest hash已改变或候选完整扫描失败时拒绝提交。版本1成功修改后转换成版本2，所有其他来源声明和明确启停值保留；不下载、安装、删除技能或自动改变来源。

原锁读取、schema/hash核验、候选策略完整扫描和发布共享现有工作区非排队协作写锁。停用可以修复已登记技能的正文漂移：只验证候选启用表，停用叶文件不读；重新启用仍须完整原始hash一致。目录和锁的链接、硬链接、FIFO、容量及单次读取边界不放宽。候选JSON不超过128KiB。写入复用0600随机暂存文件、文件sync、同目录rename和目录sync；旧锁不存在时不创建。错误诊断不输出原始锁或来源凭据。

成功JSON包含 `disk_policy` 和 `runtime_applied:false`。管理员须另外成功执行认证HTTP reload或SIGHUP并读取原进程目录，磁盘保存不是运行确认。保存不取消已选择工作、清除历史或撤销一般文件权限。

提交前失败保持原manifest字节。版本2已处于请求状态时，核验原hash后明确拒绝且不发布；版本1同值请求仍可迁移到版本2。rename后目录同步失败可能已经提交，命令非零且要求检查磁盘状态，不自动重试或回退。只提供本地文件系统上的协作修改语义，不保证断电故障的硬件行为；不协作的本机编辑器或授权文件操作可以修改技能/锁，不能把协作锁当ACL。

hash是原始内容条件，不是单调操作代次。在未再次恢复相同字节的情况下，使用同一原hash的两个改变字节的协作请求只有一个能提交；另一个须重新读取并审核。若之后有人恢复原字节，旧hash会再次匹配，不能用本合同证明没有发生中间修改（ABA）或检测所有历史操作。

该命令由操作员本机权限执行，没有加入模型工具或HTTP写入端点；原请求工具白名单、租户及读取权限不变。这是已登记加载策略的安全编辑，不是安装更新事务、发布者签名、来源审批或完整技能生命周期。

操作顺序：先运行 `jiaclaw skills policy --config /绝对路径/config.toml` 并审查目录、来源和状态，复制输出的 `manifest_sha256`。随后明确请求变更，例如：

```sh
jiaclaw skills set-enabled reviewed --enabled false \
  --if-manifest-sha256 '替换为审查过的64位小写hash' \
  --config /绝对路径/config.toml
```

核对 `disk_policy` 后再向原运行服务请求认证重载，读取该服务的 `/api/skills` 确认加载表。若原启用正文漂移导致只读策略扫描失败，操作员需直接审查原锁并核对其原字节 SHA256，然后请求停用；命令仍严格验证候选启用表。命令非零后先检查磁盘状态与错误，不用自动重试掩盖过期条件或可能已提交的同步错误。
