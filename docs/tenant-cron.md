# 独立用户定时任务

本批将定时任务接入独立用户网关的准入边界。每个用户仍拥有独立后端、工作区和数据库；任务、运行历史与结果保存在对应后端。网关仅在用户已启用、没有待核对的操作并取得执行容量后派发。本批已完成本地双租户进程与 Chromium 验收；最终 PR #71 head `949aebb` 的 [CI 37089235842](https://github.com/jiawenyao401/JiaClaw/actions/runs/37089235842) 已通过 Linux/macOS 与真实容器验证。

## 启用与授权

管理员在网关配置中显式设置 `scheduled_jobs: true`，并将 `request_timeout_seconds` 设为至少 150 秒（上限 300 秒，为最多 120 秒运行及提交留出余量），并将参与调度的每个后端配置为：

```toml
[scheduler]
enabled = true
gateway_driven = true

[heartbeat]
enabled = false
```

网关默认关闭这项能力。启动时必须验证后端支持网关驱动模式；该模式保留任务维护和重启恢复，但不运行自主定时 tick。网关停止或不可用期间不派发新任务。后端 API Token 只交给网关，后端保持私网可达、无公开端口；网络与存储隔离沿用[网关指南](gateway.md)。

任务沿用[调度器的错过规则](scheduler.md)：到期超过 5 秒的轮次跳过，不补跑。执行容量不足、网关停机或用户被禁用都可能错过轮次；恢复可用后继续安排未来运行。

创建任务即授权按规则重复使用该用户的模型资源，可能持续产生费用。任务归用户所有，不归创建它的某一把 Key：轮换 Key 不删除任务或解除未知 hold；禁用用户阻止未来准入，但不能撤回已经提交的模型或工具操作。

首批仅允许 `datetime_now` 和 `json_query`，每项任务明确选择至少一个工具。单次执行期限为 1–120 秒。任务不能指定模型、租户、后端、身份或外发目的地；`delivery` 被拒绝，渠道、HEARTBEAT、exec 和 MCP 后台执行不在本批范围内。模型使用管理员配置的 `routing.scheduled` 或既有默认模型。

## 工作台与 API

工作台成功连接后查询受保护的 `GET /api/gateway/capabilities`，仅当 `scheduled_jobs` 为 true 时显示“定时任务”。普通单用户服务没有这个能力接口时保持原有会话界面。

任务页支持新建、分页查看、暂停、恢复、软删除和运行结果。 网关返回 2xx 仍可能标记结果待核对；工作台会明确提示管理员核对和勿重复提交，保留聊天或任务草稿，不显示提交成功。可选固定间隔或五段 cron 表达式及 IANA 时区；创建后立即启用。名称最多 128 UTF-8 字节，任务内容最多 32 KiB。恢复前须核对上次运行及外部效果，恢复只安排将来的运行，不重放旧运行。暂停和删除保留记录，已提交的运行可能继续。

公开接口只允许当前身份管理自己后端的任务：

| 接口 | 用途 |
|---|---|
| `GET/POST /api/jobs` | 列表 / 创建 |
| `GET /api/jobs/status` | 调度状态 |
| `GET/DELETE /api/jobs/{uuid}` | 详情 / 软删除；成功删除返回 204 |
| `POST /api/jobs/{uuid}/pause`、`resume` | 暂停 / 恢复 |
| `GET /api/jobs/{uuid}/runs` | 查看运行及结果 |

列表使用 `limit=1..5`、`offset=0..10000`，返回 `{items,next_offset}`，结果受 1 MiB JSON 上限约束。只有任务列表接受 `include_deleted`。工作台逐页替换内容，每条运行正文最多展示 16 Ki 字符，超出会明确标记；完整有界记录仍在服务端。切换身份立即清除列表、结果、选择与草稿，旧请求响应不能重新填入页面；Key 仅保存在页面内存。任务结果直接展示，不链接到普通聊天会话。

内部派发接口不经过公开代理。用户输入不能指定内部派发身份，也不能让网关转发任意路径、请求头或后端地址。读取状态使用独立的控制请求容量，运行期间仍可查看记录；聊天和任务执行共享全局及对应后端的执行容量。

## 未知结果与恢复

网关先持久化准入身份，再向后端发出一次派发。后端将派发身份与任务领取在同一事务中绑定；空派发也记录结果。重复身份返回已有记录，不领取另一项任务。派发使用网关生成的 canonical UUIDv7；新身份只接受过去 60 秒至未来 30 秒的时钟窗口。数据库持久保存已观察时间的高水位，防止时钟回退后重新接收已过期身份。已完成或 idle 摘要在至少 180 秒后可回收；未决及需核对摘要不自动回收，最多保留 10,000 条，容量满停止新准入。在持久证据完整时，已回收的旧身份仍因时间窗口被拒绝。网关和后端的时钟必须同步在上述 UUID 窗口内；超出窗口的时钟偏移会拒绝派发，并可能使网关保留未知 hold，需核对时钟及请求结果后处理。必须保留时间高水位与派发摘要；清库或恢复旧副本不提供拒绝重放保证，须按停机一致备份与人工核对流程处理。

断连、错位或不完整回执、超时、进程中断时保留未知 hold；不自动重发。后端重启将未结束的运行标为 interrupted 并暂停对应任务。网关重启也不能清除未知准入。管理员应依据网关请求 ID 与后端运行 ID 核对模型、工具和数据库结果，确认后端空闲后按[网关核对流程](gateway.md#不确定写入停机与恢复)解除 hold，再由用户明确恢复任务。

停机先停止网关派发并排空，再停止后端；备份 registry 和各租户数据库必须保持一致的停止窗口。它们不是一个跨服务事务，恢复旧副本前必须核对备份点之后的准入与外部效果。当前批次将会话数据库升级为 schema 8；升级前备份，旧版本程序拒绝打开，不能直接降级。
