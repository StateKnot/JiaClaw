# 用本机文本资料提问

工作台在消息草稿中提供“加入本机文本资料”。连接可写身份并选择或新建会话后，用户选择一个文件，再点击“加入草稿”。读取完成后，原草稿后追加文件名、完整文本及可读的边界标记；用户可编辑、删除或补充问题，再使用原“发送”按钮。选中文件和加入草稿都不提交任务、不调用模型、不改变工具勾选。

支持 `.txt`、`.md`、`.csv`、`.json`、`.log`，单次一个文件，原文件 1–16384 字节，文件名最多 128 UTF-8 字节。扩展名只是选择范围，不证明正文安全或语义。文件必须完整严格 UTF-8；保留 BOM、空白和制表符，将 CRLF／CR 换行统一为 LF。NUL、其他不支持的 ASCII 控制字符、非法或截断 UTF-8 拒绝，超限不会截取。加上原草稿和边界标记后的完整消息不得超过 32768 UTF-8 字节。原发送入口仍独立核对消息、完整 JSON、工具和技能预算。

浏览器使用原生 [FileReader.readAsArrayBuffer](https://developer.mozilla.org/en-US/docs/Web/API/FileReader/readAsArrayBuffer) 和严格 [TextDecoder](https://developer.mozilla.org/en-US/docs/Web/API/TextDecoder/TextDecoder)。一次读取持有原工作台 busy 状态，五秒定时取消并在返回后核对同一绝对截止。读取失败、超时或草稿在等待中改变时保留当前草稿，不部分追加。身份切换取消读取、清空文件选择和私人反馈；旧身份或旧选择的迟到完成不能恢复内容。只读身份、未选会话、原任务仍跟踪或工作台忙时不能导入。这里的取消是浏览器读取取消与结果丢弃，不是独立 OS 硬抢占认证。

文件名取浏览器所选文件的 basename，不读取用户目录路径；名称中的路径分隔符、Unicode Cc 控制字符及完整 Bidi_Control（包括 ALM／LRM／RLM、嵌入和隔离标记）拒绝。页面只将文本写入 textarea.value／textContent。文件中的 HTML、代码、指令或边界标记均是用户资料；边界标记帮助审阅，不提供提示注入隔离，也不授予工具权限。原整批工具预检、租户 scope、配额、UUID、取消 owner、收据和 hold 决策保持。

**隐私：**发送时，已加入草稿的文件名和正文会成为原消息的一部分，交给当前用户配置的模型并按原会话／模型收据规则保存。取消文件选择不会从已编辑的草稿中删除文字；用户可在发送前删掉它。加入后的文字就是普通消息草稿，沿用原会话切换行为。断开或刷新清空浏览器私人状态，不承诺删除已提交消息、供应商记录、备份或用户下载的回复。没有新的上传入口、服务端文件保存、会话探查、浏览器存储、自动发送或自动重放。

范围是明确选择的文本资料输入，不认证 PDF／图片／音视频理解、真实业务质量、经验学习、供应商、公共 TLS、Agent 浏览器操作、审批继续或 StateKnot durable。真实文件／浏览器、本地模型合同 fixture、UI 故障注入和官方新 head 资格分别记录；不借父 PR135 的资格。累计固定 `origin/main` 为 `4b2357fcf01f47ba08d7724edbba7accfb60972c`，其历史结论继承，fresh 只覆盖本批源码、适当执行和独立交付／发布身份。
