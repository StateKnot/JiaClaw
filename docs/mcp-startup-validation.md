# MCP 启动截止的阶段验收

MCP 启动总截止涵盖发现和 Schema 准入。发现尚未完成时，没有 Schema 工作应当占用许可；Schema 工作已准入时，即使等待方超时，许可也须由实际阻塞工作持有至完成。两条路径都不得将失败初始化的工具发布到注册表，不得提交 `tools/call`。

测试先观察真实 localhost `server/discover` 或实际 Schema 许可准入，再使原配置的一秒截止到期。时钟在阶段设置期间暂停，随后推进原截止并恢复；独立真实五秒设置和两秒结算 guard 限定测试本身。传输和启动总截止同时到期时，原有脱敏发现错误或启动截止错误都可以先返回。测试不重置生产截止，也不证明物理一秒冷启动。

发现负例还释放并等待已放弃响应的发送尝试实际结算，再确认原注册表为空。Schema 负例等待实际阻塞工作结束后确认许可恢复。两者最后用新的正常五秒配置启动，确认批准工具已注册且没有调用远端工具。代码变更仅位于 `cfg(test)`；生产初始化、凭据、注册、并发和取消代码保持逐字节一致。

历史默认并行 Rust 曾出现预期三个许可、实际四个的断言失败；原日志没有记录阶段，具体历史触发路径仍未确认。受控真实发现延迟让旧断言连续三次出现同一失败，证明阶段混淆能产生该症状。新测试分别验收两个阶段，不将旧独立或串行重跑通过称作修复证据。初版暂停时钟的结算错误，以及首次错误文案断言使用英文前缀的夹具错误，均保留独立日志。

每批本地源码资格与新固定 head 官方资格分别记录。此修订不扩大现有只读 HTTP MCP 范围，不认证供应商、stdio/OAuth、外部写入或 durable 恢复。
