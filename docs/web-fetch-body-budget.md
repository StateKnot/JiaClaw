# 网页正文在读取时受限

`web_fetch` 继续使用已有 minreq 客户端、HTML 提取和工具注册。成功响应最多向应用正文缓冲区读取 1 MiB + 1 字节：前 1 MiB 用于原文字提取，多出的一个字节仅用于确定 `[truncated]`，不进入正文。到达上限后释放原响应及其连接，不等待剩余正文或连接关闭。固定长度、chunked 和以关闭结束的 HTTP 响应均采用同一路径。

这是应用捕获的正文上限，不是完整进程内存或网卡接收字节的上限。minreq 的原 16 KiB 网络缓冲、TLS、响应头、HTML 提取和输出分配仍独立存在；不按 `Content-Length` 预分配正文，也不将服务器声明当作实际字节数。未改变响应头限制或提供通用下载工具。原始正文恰好 1 MiB 时没有因原始字节预算产生的截断标记；原 `max_chars` 仍可独立截断文字。

重定向与非 2xx 响应从原响应头决定后续行为，不下载其正文。客户端使用正式 with_follow_redirects(false) 关闭自动跳转，交给原循环逐跳 URL 校验，最多五次；原 with_max_redirects(0) 实际在该循环前报错，本批真实302正例和五次循环上限覆盖该应用接线修复。204 保持无正文语义。现有 http/https、默认拒绝私网、本机管理员可显式开启 `allow_private`、原 HTML 文字语义和 UTF-8 有损解码均保留。该修订不认证 DNS 解析与连接地址原子绑定或独立网络沙箱。

原 15 秒 HTTP 总截止及工具注册表截止不增加；成功返回前再次检查同一 HTTP 截止。阻塞工作不是 OS 硬抢占，外层取消不证明线程已经结束，也不会自动重试请求。没有新 reader、HTTP 引擎、工具、依赖、存储或租户权限；个人 Key 的工具范围不扩大。远端请求及其服务器日志仍可能发生，不声明错误为无副作用。

提取的是有界网页前缀。截断页面可能缺少尾部事实，模型回复不能证明网页全文或研究质量；没有加入真实 Agent 浏览器、登录、截图或表单提交。

本批验证见 [验收范围](web-fetch-body-budget-validation.md)。
