# 单实例定时任务工作台

单实例 `jiaclaw serve` 的工作台可以查看和管理持久任务，并用预先生成的创建 ID 核对不确定的创建结果。它使用实例管理员 API Token；独立用户网关的任务权限和准入仍按[多用户调度指南](tenant-cron.md)执行。接口和页面已接线，本机验收结果与跨平台验证边界见文末。

## 启用和能力探测

```toml
[scheduler]
enabled = true
gateway_driven = false

[heartbeat]
enabled = false

[http]
bind = "127.0.0.1:8080"
persist = true
persist_path = "../state/sessions.sqlite3"
```

另以受保护配置或环境变量提供 `JIACLAW_API_TOKEN` 与 Brokerrouter 虚拟 Key；完整启动、工具和调度限制见[定时任务配置](scheduler.md)。管理员 Token 可管理此实例的全部任务，远程访问应使用可信网络和 HTTPS。创建并启用任务意味着授权按计划持续使用模型及指定工具；相应费用和配额仍由配置与网关预算约束。

连接工作台后先查询 `GET /api/gateway/capabilities`。仅该接口返回 404 时，页面才尝试管理员 `GET /api/jobs/status`，并要求明确声明 `create_identity_protocol: "job-id-v1"`。网关明确返回 `scheduled_jobs: false` 时不回退到后端权限；旧服务没有新协议字段时也不猜测支持安全创建。

standalone 状态包含 `state`、`max_concurrent_runs: 4` 和创建协议标识。运行异常或停止准入时，已有任务仍可查看、暂停或软删除，但新建和恢复须满足当前服务状态与授权。配置 `scheduler.enabled = false` 会使任务管理接口返回 404；要核查已有任务，应保留调度器启用并暂停具体任务，或在受控停机窗口维护数据库。不要把关闭网页解释成停止调度。

## 查看和管理

任务每页 5 项，运行每页 1 项。单实例 API 返回裸数组，工作台按有界 offset 翻页；`limit` 和 `offset` 的完整 API 范围见[管理接口](scheduler.md#管理-api)。页面可按任务 UUID 直接定位，包含按 ID 查询已软删除任务的状态。任务列表可以选择包含已删除记录；筛选或翻页只有在成功读取并校验目标页后才提交，失败保留旧筛选与页码。软删除和运行记录保留规则不变。

详情展示当前任务的完整授权字段：工具名、执行期限、计划和渠道目的地（如有），以及当前启用/删除状态、提示词和运行结果。已有通过 API 创建的受控 exec、MCP、通知目的地或超过 120 秒的任务不会被页面伪装成新建表单的较窄权限。长正文以有界纯文本显示并标记截断，完整记录仍保存在服务端；不执行模型或平台文本中的 HTML。

页面的新建表单只提供 `datetime_now`、`json_query`，至少选择一个工具；执行期限为 1–120 秒，不配置 `delivery`。这只是表单的授权范围；standalone 管理 API 仍支持符合当前配置的高级任务。修改现有任务需明确暂停/删除旧任务并创建新任务，PUT 创建接口不是编辑接口。

暂停和软删除阻止未来领取，已提交的模型、工具或投递可能继续。恢复仅安排未来运行，要求调度器正在接受新工作、当前工具/目的地授权仍合法，并先处理旧运行尚未核对的投递；它不重放中断运行，不恢复旧工具循环，也不撤回已发送的渠道消息。旧投递可通过[发件箱审计](web-outbox.md)核对。页面不提供 purge。

## 有持久创建身份的 API

`PUT /api/jobs/{id}` 是 standalone 管理员的 create-only 操作。客户端必须在第一次请求前生成并保留一个**规范小写 UUIDv4**，正文为既有 JobSpec。新任务、初次下一运行时间和创建收据在同一个 SQLite 事务中保存；成功后任务立即启用。

| 情况 | 响应与行为 |
|---|---|
| 新 ID、合法当前策略、调度器 running | 201，返回新 Job |
| 同 ID、同 typed JobSpec 且已有创建收据 | 200，返回该 Job 的当前状态，不再创建或改变下一次运行时间 |
| 同 ID、不同 JobSpec | 409，不修改原任务 |
| 已有同 ID 旧任务但没有创建收据 | 409，不自动认领旧任务 |
| 新 ID 对应的 `job:<id>` 会话已被遗留或导入数据占用 | 409，不继承旧会话上下文，不创建任务 |
| 任务已 purge，但创建收据仍在 | 409，ID 永久退役 |
| 创建收据达 10000 条 | 新 ID 返回 409；已记录且任务仍在的相同请求仍可回读 |

相同请求在任务暂停或软删除后返回当前暂停/删除状态，不重新启用。即使调度器 failed/stopping 或原工具授权被撤销，已知收据的同正文回读也不需要通过新建准入；它仍要求调度器配置启用、有效管理员 Token 和 SQLite。新建始终检查当前状态、工具和目的地策略。

“相同”指服务器按类型解析 JobSpec 后序列化并计算 SHA-256，不是直接比较 HTTP 字节：JSON 对象键顺序不影响；省略 `timeout_secs` 等价于 120；`delivery` 缺省和 null 等价。`enabled_tools` 的数组顺序有意义，交换顺序会冲突；名称、提示词、cron 表达式和时区按精确字符串比较，不自动 trim，也不将同义 cron 或时区别名合并。未知字段按 JobSpec 合同拒绝。

旧 `POST /api/jobs` 保持兼容，每次由服务器生成新 ID，**没有上述创建结果核对保证**。不要在请求结果未知后改用 POST 或换一个新 ID 重试。独立用户网关不代理该 PUT；即使直连 gateway_driven 后端，PUT 也返回 404，不能绕过网关写入准入。

## 创建响应丢失后的处理

standalone 表单在首次发送前固定本次 UUID 和 JobSpec 快照。创建期间显示待核对身份；HTTP 超时、断网或不完整响应时，页面保留该身份与快照，并通过 GET 查询同一 ID，不自动重发 PUT。

1. GET 找到任务时，核对 ID、配置和当前启用状态。创建请求可能早已成功，任务甚至已经运行；暂停或软删除状态不能当作需要重新创建。
2. GET 未找到或查询仍失败时，不能仅凭这次结果判定原 PUT 没有提交。保留原 ID 与完整快照；没有已知冲突且调度器 running 时，可选择页面的显式重试。重试仍发送同 ID、同快照的 PUT，由持久收据避免第二次创建。
3. PUT 返回 409 后，页面保留服务器拒绝原因及原 ID/快照，并禁用同 ID 重试。后续 GET 返回 404 或失败不会覆盖这项拒绝；仍可继续 GET 核对，匹配的 200 记录可确认当前结果，也可明确选择放弃跟踪。返回任务身份或配置不匹配时同样应停止修改并人工核对；页面不会为消除冲突自动生成新 ID。
4. “放弃跟踪”只清理浏览器中的待核对状态，不会取消、暂停或删除可能已经存在的任务。随后创建新任务可能使两个计划同时生效，必须先查清原 ID。

待核对 ID、正文和 Token 仅保存在页面内存，不写 localStorage、sessionStorage 或 Cookie。切换身份、刷新或关闭页面会丢失内存快照；在离开前保留任务 UUID 和必要核查资料，再通过 UUID 查找或管理 API 恢复审计。切换身份及 401 会清空旧任务、结果与草稿，并丢弃旧请求的迟到响应。

工作台对任务 HTTP 响应实施最多 2 MiB 的读取限制，每个任务请求等待最多 30 秒；较大或畸形响应会被拒绝，而不是继续解析不完整结果。此期限只取消浏览器等待，不能证明服务端事务、模型或工具已经停止。结果核对与显式重试是不同操作，重试不应改动已固定的正文。

## 数据库、容量和备份

本批会话数据库升级至 schema 10。创建收据只保存 ID 和 JobSpec 的 SHA-256，不另存提示词；任务本身仍保存完整 JobSpec。收据独立于任务外键，显式 purge 后仍保留，同库最多接收 10000 个创建身份，永久不自动清理。任务本身仍受含软删除记录共 100 项的限制；清理任务可以释放任务容量，不能释放创建身份容量。

收据满额时新 PUT 会停止准入，已有任务、审计与相同收据回读保留。产品没有安全遗忘旧 ID 的自动策略；不要直接删收据或把旧 ID 当作可重复使用的键。备份和迁移须在一致停机窗口包含完整 SQLite 状态及收据，升级前备份；旧版本不能直接打开 schema 10。

该保证依赖同一数据库的持久历史。删除库、手工删除收据、恢复早于创建的备份或另换数据库，都会失去相应身份记录；程序无法在丢失历史后继续证明旧 ID 没有使用过。回退前必须核对备份点之后的创建、运行及外部效果，不能将数据库恢复视为对平台或模型操作的回滚。
