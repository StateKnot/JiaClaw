# 原请求的任务步骤与工具记录

工作台在同一原请求编号下展示两份独立事实。使用已有已启用的 HTTP JSON/SSE 能力，不增加工具权限、模型调用或探查入口。

“本页观察到的步骤”消费原 SSE Parser 已核对的 model_started、model_completed 和 tool_completed：分别是模型请求已提交、模型收据已保存、工具已返回。预览文字不算步骤；工具返回可能是错误或未知效果，不能标为成功、完成率或恢复检查点。断流保留本页已经看到的部分，仍须按原编号核对结果。原 GET、active/needs_review、草稿、取消 owner 和所有原期限仍决定执行占用与结束跟踪。

“原收据保存的工具”仅在原 JSON 快照通过既有身份与授权验证后读取 result.tool_names，按原顺序保留重复名称；不是完整持久执行时间线，也没有参数、结果、费用或逐工具成功判定。结果已清理、尚未取得或读取失败时明确没有当前已核对的记录。实时 done 不能代替原 GET。JSON 任务与刷新后的原 UUID 查询不会补造模型轮次或实时事件。

执行中手动 GET 的 freshness 只属于该次收据。后续 done 替换收据时明确失效，新的工具记录必须等原最终 GET 通过，不能沿用先前 running 快照的核对状态。

两份列表各最多展示128条，超限明确显示观察/保存的总数与省略范围；不会因展示达到上限而停止解析、重新提交或改变结算。所有模型与工具名称以 textContent 渲染，并在手机换行。切换身份、新跟踪原请求或结束跟踪会清空私人 DOM；迟到旧响应仍受原 identity/attempt 校验约束。只有非秘密原 UUID 留在 URL fragment，不增加 browser storage、poll、自动重连或模型请求。

此能力提供用户可读的任务进展和工具记录，不认证 Agent 浏览器工具、durable 图恢复、子 Agent、审批继续、真实供应商、经验质量或任务成功率。页面 Chromium 测试仍只认证用户工作台。

## 验收范围

真实 standalone 两轮模型及 file_write 返回，核对原收据的工具顺序；租户 protocol2 的提交与收据事件；租户旧 JSON 和只读原 UUID 的无补造记录；原结果清理、断流、身份切换与迟到响应；128行展示预算和文本注入/手机布局。使用已有本机 loopback fixture，不使用付费模型或真实渠道。新增 head 必须独立完成七作业、四候选安装归档/API摘要和既有所有验收，不能借父 PR133 的资格。
