# 创建第一份技能来源锁

本机管理员 `skills create-lock` 从工作区内已审阅的 JSON 创建第一份来源锁。它解决 `register` / `set-source` 必须已有锁的首用门槛；现有来源锁仍由原条件编辑命令维护。

```sh
jiaclaw skills create-lock --from reviewed-policy.json \
  --if-source-sha256 REVIEWED_RAW_JSON_SHA256 --config config.toml
```

显式配置必须使用 `agent.skill_lock_required = true`。输入是工作区相对普通单链接 UTF-8 文件，最多128KiB；拒绝绝对路径、穿越、链接、硬链接、FIFO、目录及无效/重复/未知 JSON 字段。`--if-source-sha256` 必须匹配本次实际捕获的完整原字节。只接受版本2且每项明确 `enabled:false`，最多64个唯一目录，来源沿用无凭据 HTTPS、固定40/64位 Git 对象ID与完整原始 SKILL.md SHA256。

创建、输入捕获/摘要、每项正文能力读取/解析/原字节核验、完整目录严格扫描、私有文件同步与原子 create-if-absent 发布，必须由原非排队 workspace writer 实际持有到结算。所有声明的正文均需现存且可安全读取；正文合计最多2MiB。沿用单正文128KiB、目录256项和原元数据/参考声明预算；验证有原始2秒协作截止，不承诺阻塞操作系统 I/O 的硬截止。未登记的实际技能、缺失/漂移/不安全正文或目录均在发布前拒绝。

只有目标缺失时才创建 `skills.lock.json`，不覆盖已有普通锁；不安全目标同样拒绝。成功发布保留审阅输入的完整字节，输出其原始摘要、停用目录策略和 `runtime_applied:false`。两个相同输入并发请求最多一个成功；同输入重复执行仍拒绝，不当成幂等成功。提交前拒绝不创建锁，普通失败不残留暂存文件。发布后目录同步/暂存链接清理失败可能已创建文件，或进程中断导致结果未知，必须先按原摘要核对磁盘，不能自动重发；残留暂存文件不作为来源锁加载。

随后用新锁 hash 明确启用选定目录，再对原配置的服务认证 reload / GET，或在该配置下重启服务。磁盘创建不修改运行服务已捕获的锁策略，不自动加载技能、初始化模型/MCP/索引、发起收费请求或更改配置。已有技能正文权限、通用工作区写权限、租户工具范围和选中的只读工作保持原合同。

来源是管理员声明，不证明发布者、Git 远端或参考文件整包身份；参考读取仍在实际读取时独立核验。hash 是内容条件，不是单调操作代次或 ABA 证据。本命令只创建单个政策文件，不下载/安装/回滚技能目录，也不提供多文件安装事务、独立 ACL、签名或 durable Agent 恢复。现有安装事务、经验记忆、真实供应商/安装与业务试用里程碑继续开放。

验收要求是同一真实 CLI 的旧二进制缺能力负例与最终成功/重复/竞争/输入和正文边界、OS 权限/容量失败、实际持锁拒绝及未加载模型陷阱。官方新固定 head 的七作业、必需 Python/浏览器与四优化候选必须独立核对，不能借父 PR120 或本机证据。
