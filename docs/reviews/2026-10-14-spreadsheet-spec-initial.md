After an explicitly recorded, syntax-only route response renaming the helper, real Worker probes accept `sheetFormatPr zeroHeight="1"` and `"true"`; an actual FileReader/UI extraction appends the hidden-row cells to the draft. `sheetFormatPr` is accepted but its hidden-default setting is ignored (`spreadsheet-input.js:79–84`). - **P2 — Escaped cell strings lose value semantics.** Spec line 9 promises “原始值” and “JSON 转义保持单元格字节语义”. `text()` copies ST_Xstring escape spelling unchanged: my real Worker and UI import `A_x000D_B` literally rather than `A\rB`. `_x0000_` is accepted rather than rejected by the promised control-character policy. [Microsoft’s ST_Xstring contract](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/bd0aa042-434a-4ca7-b25f-4e1fd25a954d) requires carriage-return escaping. Decode once, including escaped underscores, and validate the decoded value, or reject unsupported escaped strings atomically.

Traversal checks element namespaces only, while allowed-but-uninspected containers admit arbitrary nested elements. Independent actual Worker probes accept `other:formula` in `urn:foreign` and `<sheetPr><unknown>…</unknown></sheetPr>`, then return a partial ordinary-cell result.
