# 可继续的工作区初始化

`jiaclaw init [--path DIR]` 默认检查同一工作区，保留已有常规默认文件及示例技能，只补缺失项；已有来源锁的技能命名空间除外。新目录、已有空目录和中断后的部分目录都使用 `Workspace::init_with_overwrite(..., false)` 的原安全初始化路径，不再因路径存在而提前报告成功。完整安全工作区重复执行可以成功，不覆盖用户编辑。

初始化错误以非零退出：例如目标为普通文件、默认叶文件是链接，或技能父目录是链接。链接外部内容不得修改。原普通文件/单链接/容量检查、目录能力、原子 create-if-absent 与非排队写锁继续由原文件模块执行，本批不复制文件协议或扩大权限。

没有来源锁时，显式 `--force` 保持原覆盖常规默认文件和示例技能的合同；初始化是单文件发布，不是整个工作区事务。出现错误时，前面的缺失文件可能已创建；修正原因后可不带 `--force` 继续。已存在的特殊文件或不安全链接不会自动删除、替换或跟随。先备份生产工作区，不把 `--force` 当作恢复。

成功说明区分“默认文件与示例技能”和“全部新建”，并明确不改配置。`--path` 只选择初始化目标，模型运行仍由配置的 `agent.workspace_path` 决定；用户须核对目录、网关 URL、逻辑模型和 Key，并用同一显式 `--config` 运行 `doctor` 和聊天。本命令不创建模型配置、不提交模型/MCP/embedding 请求，也不认证真实供应商、完整首用任务或 durable 执行。

固定父二进制的三组负例：部分目录缺失文件未补齐却返回0、普通文件根返回0、链接默认文件返回0。最终真实 CLI 重验上述三组，另在 `tests/memory_io.py` 覆盖部分根及嵌套技能恢复、其余操作员文件逐字节保留、两模式叶/父链接拒绝、原 `--force` 替换和0600权限；本批官方固定 head 跨平台资格独立验收，不能借父 PR #118 或本机结果。

## 已有技能来源锁

当工作区已有普通单链接 `skills.lock.json`，默认和 `--force` 两种模式都不补种或覆盖示例技能，也不创建其缺失父目录；已登记正文、停用目录和来源锁的字节与身份保留。顶层四个默认文件仍按所选模式恢复或覆盖。技能父链接仍拒绝，但受管理叶文件不打开；初始化不代替严格技能扫描，锁的 JSON、来源、启停和正文摘要仍由 `skills`、`doctor`、启动或认证重载检查。

来源锁的安全身份检查与每个示例文件的发布共用原工作区非排队 writer，避免协作写入在检查和发布之间插入来源锁；不使用跟随链接的 `exists()` 判断。来源锁若是符号链接、硬链接、目录或特殊文件则非零退出，不通过它触发跳过或读入外部内容。普通锁的存在是命名空间保护信号，不认证其内容或发布者；非协作编辑器仍不受该锁序列化。
