# Explicit tenant keyword memory search

This slice lets a tenant explicitly reuse prior notes through the existing `memory_search` tool. Both `http.tenant_memory_search` and the corresponding gateway backend permission are omitted by default. Each contains `paths`: 1..3 sorted unique exact canonical relative paths drawn from that agent's configured MEMORY, SOUL and USER files. Paths are at most 256 UTF-8 bytes and 16 components; aliases, hidden components, control characters and backslashes are rejected. The native agent requires tracked tenant mode and the original memory_search tool enabled.

The independent permission protocol is 1; SSE remains protocol 2. The complete descriptor contains the exact paths, keyword mode, 524288 per-source bytes, 1572864 aggregate bytes, 1024 query bytes, 20 results, 1024 excerpt bytes and 65536 result bytes. Its SHA256 covers the canonical tuple `[1,paths,"keyword",524288,1572864,1024,20,1024,65536]`. It identifies permission, not source contents, a generation, readiness, source authenticity or ABA protection. Native and gateway authenticate complete descriptor equality at startup and before each new admission, before registry identity, hold or backend PUT. Only a selected memory_search request captures `memory_search_policy_sha256`; absent fields preserve legacy fingerprints.

The existing MemorySearchTool accepts only query and optional integer max_results in 1..20 when restricted. Schema and execution reject paths, mode and all extra arguments. Within its original nonqueued blocking IO owner, it retains the original root capability and cooperative workspace writer for one complete capture of every configured source. Missing, linked, unsafe-parent, hardlinked, special, invalid UTF8, NUL or oversized sources reject the whole search. It neither truncates sources nor skips trailing sources after reaching the result limit. Matching and excerpts use the existing keyword engine. Standalone unscoped search retains its existing overrides, truncation warnings and semantic option.

Search issues no embedding request, semantic refresh or new storage operation. The original agent still rereads configured SOUL/USER/MEMORY for every turn independently of explicit search selection; withholding search does not remove that ambient prompt memory. Operational startup retains original SQLite initialization and pending normalization. This is cooperative application permission, not an independent OS ACL or protection against administrator edits/exec. The workspace writer serializes cooperating mutation; no claim is made for noncooperating edits, atomic multi-file external snapshots or physical power loss.

Permission changes require stopping and restarting both endpoints. Existing UUIDs retain their original captured permission and factual receipts without redispatch; unknown holds never clear merely because policy changed. Read-only, revoked keys, cross-user ownership, original model/turn budgets and explicit cancellation continue to apply. Ordinary read failure and waiter timeout remain known NoEffect and allow model correction. Cancellation stops future dispatch; an actual blocking reader keeps its original IO permit and writer until settlement, without OS preemption.

The workbench verifies the entire descriptor and canonical hash with secure WebCrypto, shows all exact paths using textContent, and starts with search unchecked. Only explicit selection captures permission. Identity changes clear private scope and selection; late crypto cannot restore old identity or dispatch. No storage, polling, private memory inspection or automatic model request is added. Explicit sends may forward authorized excerpts and existing ambient memory to the user's configured model. Channel and cron retain their two-tool contract.

Already authorized public acceptance seams are agent/tool, native HTTP, paired gateway, browser capability/identity and the original OS reader ownership. Tests cover two real tenant model/tool tasks, exact captured scope, wrong policy and arguments, complete trailing-source rejection, full bounds, unsafe-source matrix, real blocked reader plus cancellation, revocation/restart/history and browser identity.
