# 已锁技能的持久启用与停用

此合同在 `agent.skill_lock_required = true` 下增加锁版本 2。版本 1 保持原有全部启用语义；版本 1 不接受 `enabled`，版本 2 每条记录必须显式提供布尔 `enabled`，省略、null、重复键、未知字段和其它版本均拒绝。目录、来源声明、固定修订号、原始 SKILL.md hash 和全部资源预算沿用来源锁合同。

```json
{
  "version": 2,
  "skills": [{
    "directory": "reviewed",
    "enabled": false,
    "source": {
      "repository": "https://github.com/example/skills",
      "revision": "0123456789abcdef0123456789abcdef01234567",
      "skill_sha256": "替换为管理员核对的完整SKILL.md原始SHA256"
    }
  }]
}
```

管理员审查并原子替换锁文件，然后认证调用 `POST /api/skills/reload`，或在 Unix 向服务发送 SIGHUP。完整成功扫描后才替换进程表；仅修改磁盘锁不改变运行中的表，失败重载保留旧表。CLI `skills reload` 仍只扫描，不通知服务。此批不增加写入端点、自动安装或锁文件写入工具。

停用记录保留来源声明，但不读取或解析其 SKILL.md、不绑定正文或参考资源，也不进入已加载表。普通停用目录中即使叶文件缺失、漂移、无效 UTF-8、链接或 FIFO，都不读取；目录扫描仍有界，技能根及已存在一级技能目录的符号链接仍拒绝。停用目录允许完全删除，声明保留跨重启；启用目录则必须存在且完整原始 hash 一致。未登记但有 SKILL.md 的目录继续拒绝，重复名称仅对已加载技能检查。

成功重载或新启动后，停用项退出模型摘要、关键词及显式正文注入，后续 `skill_read` / `skill_resource_read` 选择被拒绝；重新启用前必须核对磁盘字节及声明。已经选择的只读工作仍持有原版本和 I/O 许可，可以结算；该操作不取消模型请求、抹除会话中已经发送的正文或撤销其它通用文件读取权限。授权边界仍是原请求工具白名单与工作区权限。

`jiaclaw skills policy --config /绝对路径/config.toml` 在必需锁配置下只读扫描并输出 JSON：实际锁字节的 `manifest_sha256`、版本与按目录排序的全部声明（包括停用项），每项包含明确 `enabled` 和 `source`。输出来自一次锁读取与使用同一锁的严格扫描；它描述磁盘策略，不能证明运行服务已经应用。锁关闭时命令拒绝而不暗示策略生效。一般列表和认证 `/api/skills` 继续只展示已加载表。

来源仍是管理员声明，hash 不是签名；锁共享现有工作区写权限。持久停用是经成功重载的加载策略，不是独立路径 ACL、运行取消、自动更新、安装事务或完整技能生态。无真实供应商凭据使用。固定源码、本地真实进程、双轴审查和官方候选分别验收，不借父批资格。
