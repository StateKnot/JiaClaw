# 技能同步暂停阶段验收

本批只修安装/更新验收夹具；生产 writer、fsync、目录发布、恢复身份、权限和期限不变。

## 实际停止收据

测试动态库在原同步成功后写标记，再发 SIGSTOP；标记可见不保证进程已停止。安装与更新的实际调用共用 `tests/stopped_child.py`，只针对本测试直接 child 读取 `waitpid(WUNTRACED | WNOHANG)` 的 SIGSTOP 收据。在取得收据前，不执行该阶段的并发观察、SIGCONT 或 SIGKILL。

标记等待与内核收据等待共用调用方原绝对截止：安装10秒、更新15秒。收据超时、其他停止信号或提前退出均拒绝，不重发 SIGCONT、不重启原操作、不延长生产或夹具截止；仍由原 finally 结算本任务 child。正常恢复后的原10/15秒结算等待保持。

更新第7组对原全部 HTTP、停用策略、目录身份及显式启用/reload 断言执行正常与400毫秒标记→SIGSTOP延迟两种情况。延迟只在测试动态库的显式环境变量内，生产没有故障注入开关。安装原11组与更新原八组的容量、冲突、跨账本身份、SIGKILL、EIO及原owner断言全部保留。

## 证据边界

PR123 修订前 macOS ARM 候选114423878178在更新第7组单次 SIGCONT 后 communicate 的原15秒等待超时；此前其单测/优化构建和其他七更新组通过，发行归档/发行安装未执行。远端日志没有实际停止状态或恢复阶段收据，具体历史根因未确认。

冻结生产 binary 的原八组本机通过；同一真实 CLI/鉴权 HTTP 路径中，测试库仅把标记→SIGSTOP延迟400毫秒，旧夹具在进程尚未停止时发 SIGCONT，随后实际停止并触发同15秒超时。修订先观察真实 SIGSTOP 后，原受控负例通过。这证明夹具竞态可以真实复现，不证明其为历史 ARM 唯一原因，也不认证物理断电、供应商、发行安装或 StateKnot durable。
