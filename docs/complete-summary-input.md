# 长资料完整进入会话摘要

开启原 `session.summarize_on_overflow` 后，原 CLI／普通聊天／渠道的会话溢出摘要完整接收所选旧消息；不再把每条消息裁到800字符。长资料尾部的交付格式、禁止动作、标识符和来源能进入原摘要请求。无需新增工具、模型端点、存储或配置。开启后，原800字符之外的所选旧正文也会发送给本用户配置的摘要模型；内容可能含私人资料。

格式仍是按原顺序 `User: `／`Assistant: `／`System: ` 加完整正文，各消息间一个 LF。正文的 UTF-8、BOM、TAB、CRLF、空白和内嵌换行原样保留。整份格式化输入（含角色和分隔符）最多262144 UTF-8字节；恰好上限允许，超出一字节拒绝整个摘要输入，绝不发部分摘要。先完整核算再分配输出和调用模型；错误不含私人正文。

仍用原 Summary 用途、单次无工具补全和最多512输出 tokens，以及原模型调用身份、持久收据和 unknown hold。摘要返回后保留原 `keep_recent` 完整消息并写入原会话存储。摘要输入超限、已知提供商失败或空输出时沿用原硬截断回退；旧消息可能丢失。未知模型提交仍阻止上层会话提交，不能借回退解除 hold 或重发。

默认开关关闭；关闭时仍硬截断。显式 stub 和导入会话仍是原有本地 digest，不请求模型且不保证全文保留。此功能只保证摘要请求接收完整允许输入，不保证模型生成摘要保留每项事实、不认证真实任务质量或经验学习。历史摘要已经丢失的内容不能恢复。未启用摘要、超限回退、无摘要路径均不能据此声称保留了全部旧上下文。

tracked `/api/turns`／个人 Key 工作台仍按原历史预算拒绝超限，不新增隐式摘要或模型请求。本批改善原已有摘要入口，不改变 tracked 任务授权、权限、UUID、期限、取消或效果边界。

验收要求：真实本地模型端点核对262144字节出站输入逐字节完整（含800字符后的尾部约定和多字节正文）、原单次 Summary 路由／无工具／512上限，262145字节零摘要请求并精确原硬截断；两份会话 SQLite 重启后逐消息相同且无模型重放。纯单测另核单条长消息、多消息合计、角色及分隔符计费、空输入与多字节边界。fixture不能代替正式供应商、计费、公网TLS或模型经验质量认证。
