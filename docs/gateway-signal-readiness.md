# 网关监听前的 Unix 停止信号所有权

网关在绑定 TCP 监听端口之前注册并持有 SIGTERM、SIGINT 接收器。任一个注册失败都使启动失败，不对外提供监听端口。注册后的启动阶段收到信号，事件保留在原接收器中；进入原关闭选择分支后关闭准入，再按原请求超时加五秒共享截止完成结算。没有添加第二个关闭所有者，也没有延长信号观察、请求、worker 或关闭预算。非 Unix 的 Ctrl+C 路径保持原行为。

此前注册发生在 `shutdown()` 异步函数首次被轮询时，晚于 `TcpListener::bind`。TCP 三次握手可能已经成功，而 Unix SIGTERM 仍执行默认终止动作。这是生产启动窗口缺陷，不应通过延长测试等待、清除 hold 或重复发送信号处理。

固定旧二进制的本机受控验证在真实 `listen()` 成功后暂缓返回，在原 TCP-only readiness 通过后发送 SIGTERM，并在 0.2 秒释放启动。普通对照正常关闭；两个受控对照均被信号 15 直接终止，原五秒观察器拒绝。该实验控制的是本机启动窗口，不能证明之前 Hosted 作业失败的唯一原因或与旧三秒响应头超时、公共镜像拉取失败同因。

回归测试在隔离的测试子进程中创建信号接收器，在返回的关闭 future 首次轮询之前发送实际 SIGTERM 和 SIGINT，并要求原五秒内观察到事件。原七组网关关闭、准入、未知 hold、重启和迟到观察验收仍必须通过。新的源码与固定 head 资格独立验收，旧失败和已用尽的两次定向重试记录保留。
