# 写入并发验收的实际结算

工作区写入仍为非排队准入。测试让十二个真实原始调用同时竞争，收集并 join 全部实际调用后再检查磁盘结果；成功调用必须恰好写入一次，精确工作区锁上下文及 `EWOULDBLOCK` 拒绝必须没有写入。只有这些已核验的零效果拒绝才另行作为独立请求执行。未知错误立即失败，成功结果不重放；不以固定轮询次数推断实际 owner 已释放。

共享测试助手只统一并发参与者与 join。普通内存追加和文件追加保留各自内容合同：原字节、十二份唯一贡献、无换行、容量拒绝后字节不变以及无遗留暂存文件。持锁时普通写入、追加、替换和删除须准确拒绝。新增回归让真实 edit owner 在已取得原锁后等十一份拒绝收据，共用五秒接收截止，然后结算全部调用再执行独立请求；生产锁、超时、取消或权限没有变更。

PR116 初始 Linux x64 优化候选在旧测试的 200×2ms 轮询后报 `lock did not release`，优化编译和安装验收尚未开始。日志没有记录实际持锁时间，不能据此确定 CI 调度或 fsync 根因。测试模块内以真实 owner 持锁 500ms 复现旧夹具三次失败；修订测试在相同触发条件下三次通过。诊断注入已移除，生产 `cfg(test)` 前内容逐字节不变。初诊断回调返回值不符合 tuple 的编译错误另行保留，不属于生产负例。

正式完整验收使用仓库既有 `--test-threads=1` harness，所有测试内部并发参与者保留。首轮默认并行完整 Rust 另触发未修改的 MCP startup 许可断言（预期3，实际4）；同函数随后三次独立通过。失败阶段没有被诊断，串行或独立复跑通过不能称为修复该并行失败。原失败、受控 RED/GREEN、本地正式 harness 与新固定 head 的官方 CI 是不同证据，不能互相替代。

此修订仅涉及测试模块，不是工具未知效果的自动重试策略。新官方 head 仍须独立通过七实际作业、50必需Python、七Chromium及四优化候选各13安装/归档/源码检查；原候选的部分成功和父PR资格不转移。
